🔌 Tipuri de Autowiring în XML (întrebare confirmată!)

Mod Cum caută Spring bean-ul? Când pică / Observație
byType După tipul clasei/interfeței din setter (ex: ClientRepository). Pică cu NoUniqueBeanDefinitionException dacă sunt ≥ 2 bean-uri de același tip.
byName După numele proprietății/setter-ului (setRepository → caută bean cu id="repository"). Dacă în XML bean-ul are id="clientRepository" (ca la noi), byName NU îl găsește!
constructor Similar cu byType, dar aplicat pe parametrii constructorului clasei. Necesită constructor cu parametri compatibili.
no (default) Nu face autowiring automat; dependențele se leagă manual cu <property ref="..."/> sau @Autowired. Acesta e modul folosit implicit în Ex 2.

<constructor-arg> vs <property> și value vs ref

Element / Atribut Ce apelează / ce pasează? Exemplu din test-clients.xml
<constructor-arg> Apelează constructorul la crearea obiectului. <constructor-arg name="name" value="${client1}" />
<property> Apelează setter-ul (setCity, setAccounts) după constructor. <property name="city" value="Moscow" />
value="..." Pentru valori simple: primitive, String, Enum, ${...}. value="MALE", value="1000"
ref="..." Referință către alt bean administrat de containerul Spring. <property name="repository" ref="clientRepository" />
